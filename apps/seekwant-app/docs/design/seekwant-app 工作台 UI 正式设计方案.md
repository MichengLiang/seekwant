# seekwant-app 工作台 UI 正式设计方案

这是一版正式设计方案，不是实施计划。文本只定义设计对象、边界、依据、设计点和注意事项；不包含分批开发安排。后续如果进入实现，再单独写计划。

我已经按写作规范处理这版文本：对象定义不夹带过程叙事；设计点必须说明它回应的事实、服务的动作、改变的界面规约、引入的成本和验证方式；相邻对象只在阻止误读时出现；例子只作为规则的卫星材料，不替代规则本身。

## 1. 设计对象

本次设计对象是 `seekwant-app` 的工作台外壳与图谱探索界面。

该工作台承载三个核心投影：文档投影、图谱投影、节点详情投影。文档投影用于阅读 AsciiDoc 渲染结果与源文本；图谱投影用于观察 RDF/TTL 数据中节点、关系和结构边；节点详情投影用于检查被选中节点的标题、标识、业务元数据、结构诊断和源码位置。

工作台外壳负责组织这些投影的空间关系、导航关系、设置入口和状态表达。它不负责改变 TTL 解析语义，不负责重新定义 Asciidoctor 渲染契约，不负责发明新的图谱布局算法，也不负责让手机宽度承载完整图谱工作流。

本次 UI 设计的主问题是：当前界面把大量低频配置项长期暴露在顶部，导致顶部成为控制堆栈，主任务区域被削弱。设计目标是建立稳定的工作台层级，使高频动作接近被控制对象，低频设置进入可发现、可收纳、可分组的设置面，文档和图谱重新成为首屏主对象。

## 2. 当前事实

当前主页面在 `src/pages/GraphPage.tsx` 中由 header、main、footer 组成。main 区域包含左侧 `DocumentPanel`、中间 `TtlGraph`、右侧 `DetailPanel`。这个三栏结构本身成立，因为它对应用户在 seekwant 中真实发生的三个动作：阅读文档、探索图谱、检查节点。

当前 header 同时包含应用标题、当前文件标签、预置数据集按钮组、打开文件、边标签语言切换、包含关系开关、节点标签模式切换和图例。这个 header 不是单一职责的标题栏，而是数据源面板、视图设置面板、关系过滤面板、图例面板和全局状态栏的混合体。

我实际启动页面并抓取了截图。1440×900 桌面视口中，header 高度约 88px；1024×768 视口中，header 高度约 120px；390×844 视口中，header 高度约 206px。这个测量说明顶部控件不是轻量工具栏，而是在宽度不足时变成多行控制堆栈。该控制堆栈直接压缩文档和图谱，破坏工作台主对象的视觉优先级。

当前左侧文档面板已经有局部工具栏：渲染/源码切换与折叠按钮。该局部工具栏位置正确，因为它只控制文档面板。当前右侧详情面板也有局部控制：节点片段/所在文件切换、关闭按钮、结构诊断折叠。该局部控制位置也正确，因为它只控制详情内容。当前画布右下角有适配视图和退出聚焦按钮。该方向同样正确，因为它们是画布高频动作。

因此，本次设计不应推翻所有界面结构。应保留三栏工作台、文档局部工具、详情局部工具和画布局部动作；应重构顶部控制、图例位置、数据源入口和全局设置入口。

## 3. 外部依据

VS Code 的工作台结构提供了第一组依据。VS Code 官方用户界面文档将界面划分为 Activity Bar、Primary Side Bar、Secondary Side Bar、Editor、Panel 和 Status Bar。其关键原则是：视图容器由活动栏切换，侧栏承载视图，编辑区承载主要工作对象，状态栏承载上下文状态。VS Code UX Guidelines 也把 Views 放在 Sidebar 或 Panel 中，把 Settings 作为用户配置入口，而不是把所有配置长期放在编辑区上方。

JetBrains 的 IDE 结构提供了第二组依据。JetBrains Tool Windows 文档说明 tool windows 是 IDE 主窗口边缘的子窗口，通常带有自己的 toolbars，并由边缘按钮激活。JetBrains Toolbar 指南说明 toolbar 用于快速访问频繁使用的动作和设置；当项目过多时，应通过分组、下拉或 overflow 控制，而不是增加更多 toolbar。JetBrains Settings Guide 说明设置需要层级、命名和分组，配置项应进入 Settings dialog 的组织结构，而不是落入无意义的 catch-all。

Figma 的画布界面提供了第三组依据。Figma Help 将设计文件界面描述为画布之外的 toolbar、左侧边栏和右侧 properties panel。Figma 的右侧 properties panel 会根据选中对象和访问权限变化；其 toolbar 是与画布交互的 hub。该结构说明：上下文属性应在右侧，画布动作应靠近画布，长期导航应在侧边栏，设置不应抢占画布主体。

这些参考对象的共同结论不是某个视觉样式，而是界面职责分层：全局外壳只承载身份、导航和少数全局动作；对象级工具栏控制局部对象；设置面承担低频配置；状态栏表达当前状态；属性面板跟随选择对象。

## 4. 设计原则

第一原则：主对象优先。seekwant 的主对象是文档与图谱，不是设置项。首屏应让用户立即看到文档和图谱，顶部不应消耗过多垂直空间。标题栏高度应接近桌面工作台常见的 40px 到 44px，而不是随控件换行增长。

第二原则：工具贴近对象。控制文档的动作放在文档面板；控制图谱的动作放在图谱画布或图谱工具面；控制详情的动作放在详情面板；控制整个工作台的动作才放在全局标题栏。

第三原则：低频设置可收纳。边标签语言、节点标签模式、是否显示结构边、图例显示方式、文档默认视图、详情默认源码范围等配置不应长期占据顶部。它们应进入设置面板，并按作用对象分组。

第四原则：数据源是当前上下文，不是按钮展览。预置数据集和打开文件共同构成数据源选择。它们应由一个数据集选择器承载，而不是横向显示为多个常驻按钮。

第五原则：图例是解释层，不是全局导航层。图例解释当前数据的分组和颜色。它可以在左侧面板或画布浮层中出现，但不应作为 header 第二行长期占位。

第六原则：状态栏只表达状态。节点数、关系数、解析状态、交互提示和缩放比例属于状态栏。状态栏可以提供轻量入口，但不应承载主要配置。

第七原则：手机不是目标设备。该应用的核心任务依赖文档、图谱和详情的并行观察。手机宽度无法合理承载该任务。本次设计面向桌面和平板级宽度；手机只需避免严重错乱，不作为完整功能体验目标。

## 5. 目标界面结构

目标结构是：薄标题栏、左侧活动栏、左侧主面板、中央图谱画布、右侧详情面板、底部状态栏、可收纳设置面板。

标题栏是全局外壳。它显示应用身份、当前数据集、全局搜索或命令入口、导入入口和设置入口。标题栏不显示完整图例，不显示所有预置数据集，不显示节点标签模式，不显示边标签语言，不显示结构边开关。

左侧活动栏是视图容器切换面。它提供少量图标入口：文档、图例、数据源、设置。活动栏不是功能堆叠区。它只负责在左侧主面板中切换内容或打开设置面。

左侧主面板默认显示文档。文档面板保留渲染/源码切换、折叠和拖拽宽度。文档面板是阅读面，不应混入图谱显示设置。图例可以作为左侧主面板中的一个可切换视图或可折叠 section。

中央图谱画布是主工作区。画布承担节点和关系的视觉探索。画布内可以有紧凑工具组：适配视图、退出聚焦、重新布局、搜索节点、打开图谱显示设置。这些工具是画布动作，位置应接近画布边缘。

右侧详情面板是上下文属性面。选中节点时显示节点标题、标识、业务元数据、结构诊断和源码；无选中节点时可以显示图谱概览。详情面板不承载全局设置。

底部状态栏显示节点数、关系数、当前文件状态、解析状态、交互提示和缩放状态。它的高度应保持低，不能演化成第二工具栏。

设置面板是低频配置面。它可以从标题栏齿轮或活动栏设置入口打开。对 seekwant 当前场景，推荐右侧 drawer，而不是全屏设置页。drawer 可让用户调整图谱显示时保留画布反馈。

## 6. 控件归位规则

预置数据集按钮组归入数据集选择器。该选择器在标题栏显示当前数据集名称，点击后打开列表。列表包含所有预置数据集、打开本地 TTL 文件入口和当前文件信息。这样保留数据源可见性，同时消除横向按钮堆叠。

打开文件入口归入数据集选择器的动作区。打开文件不是数据集状态，而是导入动作。它可以作为列表底部的按钮，也可以作为标题栏右侧图标按钮，但不应与预置数据集并列成同一类按钮。

边标签语言归入设置面板的“图谱显示”分组。控件仍使用二段式选择：原文、中文。该设置只影响边标签文本，不改变数据本身。

包含关系开关归入设置面板的“关系过滤”分组。文案应改为“显示结构边”或“显示 containsDirectly 结构边”。该设置控制文档层级关系是否进入图谱投影。它影响画布密度，因此可以在画布工具组中的过滤入口内提供快捷访问，但不应常驻标题栏。

节点标签模式归入设置面板的“节点标签”分组。选项保持“标题名、ID、两者”。该设置影响节点 label 的投影方式，不是全局导航。

图例归入“图例与分组”面。默认可作为左侧主面板的一项；需要画布内快速查看时，可用一个小型可折叠浮层。图例显示颜色、分组名称和数量。图例不应横向排列在 header。

文档渲染/源码切换保留在文档面板顶部。该动作的作用域仅为文档面板。

详情节点片段/所在文件切换保留在详情面板。该动作的作用域仅为详情源码范围。

适配视图和退出聚焦保留在画布内。它们是高频画布动作。按钮形态应从文字按钮升级为图标按钮加 tooltip；当状态需要明确表达时，可以保留短文本。

## 7. 设置面板定义

设置面板的身份是“工作台配置与视图偏好入口”。它不是文档面板，不是数据源列表，不是图谱详情，也不是帮助页。

设置面板应以右侧 drawer 呈现。宽度建议为 360px 到 420px。drawer 顶部包含标题“设置”和搜索框。搜索框用于定位设置项；即使第一版设置项较少，搜索框也建立长期可扩展的设置契约。

设置面板包含五个分组。

第一组是“图谱显示”。该组包含节点标签模式、边标签语言、显示结构边、重排图谱动作和未来可加入的布局策略。该组所有设置都改变图谱投影，不改变源数据。

第二组是“图例与分组”。该组包含图例显示位置、是否在画布显示紧凑图例、分组字段说明和颜色说明。当前实现中分组来自 `faction`、`syndrome-type`、`type` 的回退逻辑；UI 应把它表达为当前图谱分组来源，而不是让用户从颜色猜测。

第三组是“文档阅读”。该组包含默认文档视图、文档栏宽度重置、源码字体大小和目录显示偏好。渲染/源码的即时切换仍在文档面板；设置面只保存默认偏好或重置动作。

第四组是“详情面板”。该组包含默认源码范围、是否默认展开结构诊断、是否显示业务元数据标签。当前结构诊断已经折叠，设置面可以控制默认展开策略。

第五组是“工作台”。该组包含主题、布局重置、左侧面板默认状态、右侧详情面板默认宽度、状态栏提示显示。该组管理工作台外壳，不管理图谱语义。

设置项应即时生效。drawer 不需要“应用”按钮。需要恢复默认的设置项应提供“恢复默认”动作。对画布密度影响大的设置应带短说明，例如“结构边表示文档层级，开启后关系数量会增加”。说明文本必须解释影响，不应写成帮助页教程。

## 8. 视觉语言

seekwant 的视觉语言应为工程工作台风格。界面应安静、密集、低噪、可长时间使用。颜色基础应为白、浅灰、暖白和少量蓝色焦点色。图谱节点颜色来自数据分组，不应被外壳主题抢夺注意力。

标题栏使用白色或极浅灰背景，底部一条细边线。标题栏高度固定，不随内容换行。应用名使用 13px 到 14px semibold。数据集选择器使用 compact combobox，不使用大面积深色按钮组。

活动栏宽度约 44px 到 52px。图标按钮固定尺寸。选中态使用细边线、浅底色或深色图标，不使用大块装饰色。活动栏只展示少量入口；超过少量入口时应重新审查对象边界，而不是继续增加图标。

左侧文档面板保持可读宽度。文档内容使用 Asciidoctor 官方渲染风格，不让工作台控件的字体层级干扰正文。面板 header 使用小标题和局部工具，避免装饰性卡片。

画布背景保持浅色。画布工具组使用半透明或白色小浮层，固定在角落。浮层只放高频画布动作，按钮有 tooltip。按钮尺寸稳定，hover 不应改变布局。

右侧详情面板使用面板式布局，不使用卡片套卡片。标题、标识、业务元数据、结构诊断、源码各自形成清晰段落。源码区域保持等宽字体和稳定行距。

状态栏使用低对比度文字。左侧显示数据状态，右侧显示交互提示。状态栏不出现大按钮。

图标建议使用成熟图标库，例如 `lucide-react`。适合的图标包括 `FileText`、`Network`、`Settings`、`Layers`、`Search`、`Upload`、`Maximize`、`RefreshCw`、`SlidersHorizontal`、`PanelLeftClose`。手写 SVG 只用于图标库无法覆盖的领域符号。

## 9. 平板与手机边界

桌面和平板是目标设备。工作台需要同时观察文档、图谱和详情，合理宽度应以 1024px 及以上为主要设计对象。平板横屏可以保留三栏或双栏；平板竖屏可以默认隐藏详情面板，由节点选择打开右侧 drawer。

手机不是目标体验。手机宽度不承载完整图谱工作台。设计只需保证页面不出现荒谬换行和不可关闭控制堆栈；不需要为手机设计完整图谱探索流程。该边界防止本次设计被小屏适配拖向错误对象。

## 10. 注意事项

第一，不能把顶部控件简单搬到另一个常驻横条。问题不是 header 样式，而是低频设置长期占位。把它们移动到第二工具栏或底部工具栏，只是改变拥挤位置，没有改变对象层位。

第二，不能把 Settings Drawer 写成帮助页面。设置面只呈现配置项、短说明和恢复默认。长教程、背景解释、产品介绍不进入设置面。

第三，不能把图例继续当全局 chrome。图例随数据变化，是解释层。它应跟随图谱或进入左侧视图。

第四，不能让数据集选择器丢失当前上下文。收纳预置数据集不等于隐藏当前数据源。当前数据集名称必须在标题栏可见。

第五，不能破坏现有正确局部工具。文档渲染/源码切换、详情节点片段/所在文件切换、画布适配视图都已经贴近对象，应保留其局部性。

第六，不能让设置项改变数据语义。节点标签、边标签语言、结构边显示都是投影设置。它们只能改变可视表达或过滤，不改变 TTL 解析结果。

第七，不能让工作台外壳压过 Asciidoctor 正文。文档是内容主对象，外壳应服务阅读和跳转，不应与正文标题争夺视觉重心。

第八，不能把手机完整体验纳入本轮设计目标。手机不是此类图谱工作台的合理主设备。为手机强行设计完整体验会损害桌面/平板主任务。

第九，不能用“看起来更现代”作为设计理由。每个设计点必须能回到用户动作：减少顶部噪声、提高主对象可见性、让设置可发现、让局部动作靠近对象、让状态保持低干扰。

第十，不能引入过度抽象。工作台壳层、数据集选择器、设置 drawer、图例面板、画布工具组、状态栏已经足够表达当前需求。插件系统、可拖拽自定义布局、命令面板等更大能力不进入当前设计本体。

## 11. 对齐后的最终形态

seekwant 的目标形态是一个桌面/平板工作台。

用户进入页面时，首先看到一个薄标题栏。标题栏显示应用身份和当前数据集，提供数据源选择、导入和设置入口。顶部不再出现横向预置数据按钮组，不再出现节点标签模式、边标签语言、结构边开关和图例行。

用户的主要视线落在文档和图谱上。左侧是可阅读、可切换源码的文档面板；中间是宽阔图谱画布；右侧在选择节点后显示详情。图谱动作位于画布内，文档动作位于文档面板内，详情动作位于详情面板内。

用户需要调整显示方式时，打开设置 drawer。设置按图谱显示、图例与分组、文档阅读、详情面板、工作台分组。设置即时生效，用户能在画布上看到结果。用户不需要在顶部常驻控件中寻找显示偏好。

用户需要理解颜色和分组时，打开图例视图或画布小图例。图例不抢占标题栏。用户需要切换数据时，打开数据集选择器。预置数据和打开文件属于同一个数据源入口。

这个设计的核心不是某个 UI 花样，而是工作台责任重新归位：全局外壳负责身份和入口；侧栏负责视图；画布负责图谱探索；右栏负责上下文属性；设置面负责低频配置；状态栏负责状态。该结构来自 VS Code、JetBrains、Figma 等成熟工作台产品的共同规律，也与 seekwant 当前的文档-图谱-详情任务结构一致。

这就是我建议正式采用的 UI 设计方案。
