# 右侧详情的所在文件全文模式

## 1. 功能对象

右侧详情的所在文件全文模式，是节点详情源码区的范围切换能力。用户打开某个图谱节点详情后，可以在右侧源码区从该节点的 AsciiDoc 源码片段切换到该节点所在源文件的完整 AsciiDoc 原文。

切换到所在文件全文模式时，页面使用该源文件中的文件代表节点作为当前详情节点。右侧标题、业务属性、结构诊断和中间图谱焦点都指向文件代表节点；右侧源码区显示该文件的完整 `SourceFile.raw`。

文件代表节点是与某个 `SourceFile.relativePath` 相同、且 `startLine` 最小的 `GraphNode`。该节点表示源文件在图谱中的入口。

## 2. 现有数据模型

当前功能使用 `parseTtl` 已经产出的数据，不需要修改 Turtle 数据生成，不需要扫描 fixture 文件系统。

`GraphNode` 提供节点信息：

```ts
interface GraphNode {
  id: string;
  headline: string;
  addressLabel: string | null;
  generatedAddressLabel: string | null;
  labels: string[];
  raw: string;
  relativePath: string | null;
  startLine: number;
  endLine: number;
  metadata: Record<string, string>;
}
```

`SourceFile` 提供源文件全文：

```ts
interface SourceFile {
  relativePath: string;
  raw: string;
}
```

`GraphData.sourceDocument.files` 定义当前图谱数据包含的源文件集合。该集合是右侧所在文件全文模式的文件来源。

页面层需要派生两个索引：

```ts
const sourceFileByPath = new Map<string, SourceFile>();
for (const file of data.sourceDocument.files) {
  sourceFileByPath.set(file.relativePath, file);
}
```

```ts
const fileRepresentativeNodeByPath = new Map<string, GraphNode>();
for (const node of data.nodes) {
  if (!node.relativePath) continue;
  const current = fileRepresentativeNodeByPath.get(node.relativePath);
  if (!current || node.startLine < current.startLine) {
    fileRepresentativeNodeByPath.set(node.relativePath, node);
  }
}
```

`sourceFileByPath` 用于从当前详情节点找到所在源文件。`fileRepresentativeNodeByPath` 用于从当前详情节点找到所在文件的文件代表节点。

## 3. 当前示例中的代表节点

`Book Entry` 的 `chapters/02-operations.adoc` 包含两个节点：

| 节点 | headingLevel | startLine | 文件 |
|---|---:|---:|---|
| `Operations` | 1 | 1 | `chapters/02-operations.adoc` |
| `Checklist` | 2 | 6 | `chapters/02-operations.adoc` |

该文件的文件代表节点是 `Operations`。用户在 `Checklist` 节点详情中进入所在文件全文模式时，页面应切换当前详情节点和图谱焦点到 `Operations`，源码区显示整个 `chapters/02-operations.adoc`。

`Book Anatomy` 的 `books/00-book-anatomy/parts/02-body-structure/01-body-map.adoc` 包含两个节点：

| 节点 | headingLevel | startLine | 文件 |
|---|---:|---:|---|
| `正文结构地图` | 1 | 1 | `books/00-book-anatomy/parts/02-body-structure/01-body-map.adoc` |
| `小节层级` | 2 | 6 | `books/00-book-anatomy/parts/02-body-structure/01-body-map.adoc` |

该文件的文件代表节点是 `正文结构地图`。用户在 `小节层级` 节点详情中进入所在文件全文模式时，页面应切换当前详情节点和图谱焦点到 `正文结构地图`，源码区显示整个 `01-body-map.adoc`。

## 4. 用户交互契约

### 4.1 图谱节点打开

输入：用户双击图谱节点，或通过其他现有节点打开入口打开节点详情。

状态结果：

```ts
focusedNodeId = nodeId;
inspectedNodeId = nodeId;
isDetailOpen = true;
detailSourceMode = "node";
```

显示结果：

- 右侧标题显示该节点 `headline`。
- 业务属性和结构诊断来自该节点。
- 源码区显示该节点 `raw`。
- 源定位显示 `relativePath · 行 startLine-endLine`。

### 4.2 左侧渲染文档点击节点

输入：用户在左侧渲染文档中点击 heading block 或 xref，并且右侧详情已经打开。

状态结果：

```ts
focusedNodeId = nodeId;
inspectedNodeId = nodeId;
isDetailOpen = true;
detailSourceMode = "node";
```

显示结果：

- 右侧切换到被点击节点。
- 源码区回到节点片段模式。
- 图谱聚焦被点击节点。

该规则保持既有交互契约：左侧文档点击不会打开关闭状态的右侧详情；右侧已经打开时，左侧文档点击会同步详情内容。

### 4.3 右侧点击“所在文件”

输入：用户在右侧源码区点击 `所在文件`。

计算：

```ts
const sourceFile = currentNode.relativePath
  ? sourceFileByPath.get(currentNode.relativePath)
  : null;

const fileRepresentativeNode = currentNode.relativePath
  ? fileRepresentativeNodeByPath.get(currentNode.relativePath)
  : null;
```

状态结果：

```ts
focusedNodeId = fileRepresentativeNode.id;
inspectedNodeId = fileRepresentativeNode.id;
isDetailOpen = true;
detailSourceMode = "file";
```

显示结果：

- 右侧标题显示文件代表节点的 `headline`。
- 右侧 address label 显示文件代表节点的 `addressLabel`。
- 业务属性和结构诊断来自文件代表节点。
- 中间图谱聚焦文件代表节点。
- 源码区显示 `sourceFile.raw`。
- 源定位显示 `relativePath · 全文件 · N 行`。

如果当前节点已经是文件代表节点，`focusedNodeId` 和 `inspectedNodeId` 保持该节点；源码区从节点片段扩展为完整源文件。

### 4.4 右侧点击“节点片段”

输入：用户在右侧源码区点击 `节点片段`。

状态结果：

```ts
detailSourceMode = "node";
```

显示结果：

- 当前详情节点不变。
- 图谱焦点不变。
- 源码区显示当前详情节点的 `raw`。
- 源定位显示 `relativePath · 行 startLine-endLine`。

所在文件全文模式会把当前详情节点替换为文件代表节点。用户随后切回节点片段时，显示文件代表节点的源码片段。

## 5. 右侧详情显示契约

右侧详情面板的主语始终是当前详情节点。当前详情节点决定右侧标题、address label、业务属性、结构诊断和图谱焦点。

源码区有两个显示范围：

```ts
type DetailSourceMode = "node" | "file";
```

### 5.1 节点片段模式

`detailSourceMode === "node"` 时：

- 源码内容为 `currentNode.raw`。
- 源定位为 `currentNode.relativePath · 行 currentNode.startLine-currentNode.endLine`。
- 源码区标题为 `AsciiDoc 源码`。

### 5.2 所在文件全文模式

`detailSourceMode === "file"` 时：

- 源码内容为 `sourceFile.raw`。
- 源定位为 `sourceFile.relativePath · 全文件 · N 行`。
- 源码区标题仍为 `AsciiDoc 源码`。
- 当前详情节点为该文件的文件代表节点。

行数按文件 raw 计算：

```ts
function countLines(raw: string): number {
  if (!raw) return 0;
  return raw.replace(/\n$/, "").split("\n").length;
}
```

## 6. 右侧源码区控件

右侧源码区标题行应包含范围切换控件：

```text
AsciiDoc 源码        [节点片段] [所在文件]
chapters/02-operations.adoc · 行 6-12
```

文件模式下：

```text
AsciiDoc 源码        [节点片段] [所在文件]
chapters/02-operations.adoc · 全文件 · 23 行
```

控件语义：

| 按钮 | 含义 |
|---|---|
| `节点片段` | 源码区显示当前详情节点的 `raw`。 |
| `所在文件` | 源码区显示当前详情节点所在源文件的完整 `raw`，并将当前详情节点替换为文件代表节点。 |

显示条件：

- 能找到当前详情节点对应的 `SourceFile` 时，显示 `节点片段 / 所在文件` 控件。
- 找不到对应 `SourceFile` 时，不显示范围切换控件，源码区保持节点片段模式。

样式要求：

- 使用紧凑 segmented control。
- 选中项使用深色背景和白色文字。
- 未选中项使用浅色 hover。
- 控件尺寸小于右侧 header 操作按钮，不抢占源码内容层级。
- 控件与当前应用的边标签、节点标签切换控件保持视觉语言一致。

## 7. 左侧文档栏调整

左侧 `DocumentPanel` 保持两个公共视图模式：

```ts
type DocumentPanelMode = "rendered" | "source";
```

`rendered` 显示 Asciidoctor 渲染页面。`source` 显示当前已有的多文件拼接源码视图。

左侧 header 中当前的单按钮 `切换源码 / 切换渲染` 应改为二态视图控件：

```text
[渲染] [源码]
```

该控件表达当前视图状态，不表达一次性命令。`渲染` 对应 shadow DOM 渲染文档；`源码` 对应 `sourceDocument.files` 拼接后的源码 `pre`。

## 8. 组件改动入口

### 8.1 `src/pages/GraphPage.tsx`

职责：页面级状态、派生索引和跨组件事件。

需要增加：

- `detailSourceMode: "node" | "file"` 状态。
- `sourceFileByPath` 派生索引。
- `fileRepresentativeNodeByPath` 派生索引。
- `handleDetailSourceModeChange(mode)` 处理器。

状态规则：

- 图谱节点打开时，`detailSourceMode` 设为 `"node"`。
- 左侧渲染文档点击节点且右侧详情已打开时，`detailSourceMode` 设为 `"node"`。
- 关闭详情时，`detailSourceMode` 可重置为 `"node"`。
- 点击右侧 `所在文件` 时，页面查找当前节点所在文件和文件代表节点，更新当前详情节点、图谱焦点和 `detailSourceMode`。

### 8.2 `src/pages/node-selection.ts`

职责：节点选择状态转移。

建议增加 action：

```ts
{ type: "detail-node-replace"; nodeId: string }
```

该 action 表示右侧详情在打开状态下切换到另一个节点。它用于所在文件全文模式进入文件代表节点。

状态结果：

```ts
focusedNodeId = nodeId;
inspectedNodeId = nodeId;
isDetailOpen = true;
```

### 8.3 `src/components/DetailPanel.tsx`

职责：右侧详情 UI。

建议 props 扩展为：

```ts
interface DetailPanelProps {
  node: GraphNode | null;
  sourceMode: "node" | "file";
  sourceFile: SourceFile | null;
  onSourceModeChange: (mode: "node" | "file") => void;
  onClose: () => void;
  onTransitionEnd?: () => void;
}
```

`DetailPanel` 根据 `sourceMode` 选择源码内容：

```ts
const rawSource =
  sourceMode === "file" && sourceFile ? sourceFile.raw : node.raw;
```

`DetailPanel` 根据 `sourceMode` 选择源定位：

```ts
const sourceLocation =
  sourceMode === "file" && sourceFile
    ? `${sourceFile.relativePath} · 全文件 · ${countLines(sourceFile.raw)} 行`
    : `${node.relativePath} · 行 ${node.startLine}-${node.endLine}`;
```

业务属性和结构诊断仍然来自 `node`。

### 8.4 `src/components/DocumentPanel.tsx`

职责：左侧文档渲染和源码视图。

需要将 `showRaw: boolean` 改为：

```ts
const [viewMode, setViewMode] = useState<DocumentPanelMode>("rendered");
```

`viewMode === "rendered"` 时显示 shadow DOM 渲染文档。`viewMode === "source"` 时显示多文件拼接源码。

Header 中使用二态 segmented control 替换当前单按钮。

## 9. 缺失数据处理

### 9.1 当前节点没有 `relativePath`

源码区不显示 `所在文件` 控件。节点片段模式正常显示。

### 9.2 找不到对应 `SourceFile`

源码区不显示 `所在文件` 控件。节点片段模式正常显示。

### 9.3 找不到文件代表节点

从节点进入的所在文件通常能找到文件代表节点，因为当前节点本身属于该文件。实现仍应保护该分支：找不到文件代表节点时，`所在文件` 不执行节点替换；源码区可保持节点片段模式。

### 9.4 文件 raw 为空

文件模式显示空 `pre` 或简短空内容提示。当前示例数据没有该情况。

## 12. 验收标准

实现完成后应满足以下条件：

- 右侧详情默认显示节点源码片段。
- 右侧详情能切换到当前节点所在源文件的完整原文。
- 切换到所在文件全文模式时，当前详情节点切换为文件代表节点。
- 切换到所在文件全文模式时，中间图谱聚焦文件代表节点。
- 切换到所在文件全文模式时，右侧业务属性和结构诊断来自文件代表节点。
- 切换回节点片段模式时，源码区显示当前详情节点的 `raw`。
- 图谱节点打开和左侧文档节点点击都会把源码范围重置为节点片段模式。
- 找不到对应 `SourceFile` 时，不显示所在文件切换入口，节点片段详情保持可用。
- 左侧文档栏使用 `渲染 / 源码` 二态视图控件。
- `Book Entry` 的 `Checklist -> Operations 所在文件全文` 行为有 e2e 覆盖。
- `Book Anatomy` 的 `小节层级 -> 正文结构地图 所在文件全文` 行为有 e2e 覆盖。

## 13. 实现注意事项

`SourceFile` 集合由 `GraphData.sourceDocument.files` 定义。实现不需要访问 fixture 目录，也不需要读取本地文件系统。

文件代表节点按 `relativePath` 和最小 `startLine` 计算。实现不应按 AsciiDoc 标记符号数量、DOM heading tag 或标题文本推断文件代表节点。

所在文件全文模式改变当前详情节点。右侧 header、业务属性、结构诊断、节点片段模式和图谱焦点都应以当前详情节点为主语。

右侧源码区的范围切换是详情面板内部的源码范围选择，不是新的左侧文件导航入口。

左侧源码视图继续显示 `sourceDocument.files` 拼接后的全局源码流。右侧所在文件全文模式显示当前详情节点所在的单个源文件。
